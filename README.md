# AI-Based Inventory & Parts Management System

A premium dark-theme inventory and parts management platform built with React, Vite, Express, MongoDB, and JWT authentication.

## Highlights
- Responsive dashboard with inventory metrics, reports, and forecasting views
- Workspace-isolated products, categories, suppliers, and sales
- Secure HTTP-only cookie authentication and role-based API authorization
- Read-only demo mode with a dedicated workspace of fictional sample records

## Development
1. Install frontend dependencies with `npm install`.
2. Copy `.env.example` to `.env` and set `VITE_API_URL`.
3. Install backend dependencies from `server` with `npm install`.
4. Copy `server/.env.example` to `server/.env` and set its values.
5. Start MongoDB using the connection configured in `MONGODB_URI`.
6. Start the API with `npm run dev` from `server`, then start Vite with `npm run dev` from the repository root.

The API automatically creates the demo account and isolated sample data at startup. `npm run seed` from `server` can also create the demo environment; it never deletes application data. Run backend security middleware tests with `npm test` from `server`.

## Environment variables
- Frontend: `VITE_API_URL` (the API base URL ending in `/api`)
- Backend: `PORT`, `NODE_ENV`, `MONGODB_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `CLIENT_URL`, `TRUST_PROXY`
- Set `CLIENT_URL` to the exact frontend origin. Comma-separate explicitly trusted origins when necessary; do not use wildcard origins with cookie authentication.
- Set `TRUST_PROXY` to the trusted reverse-proxy hop count for your host (often `1`); use `0` when directly exposed. Only trust proxies that overwrite forwarded-client headers so per-IP rate limits cannot be spoofed.
- Generate a private random `JWT_SECRET` of at least 32 characters. Never commit `.env` files or real credentials.

## Workspaces
- Use the workspace selector to switch between independent inventories or create a separate workspace.
- Products, categories, suppliers, sales, and dashboard queries are scoped to the selected workspace.
- Existing inventory is preserved in a shared **Main workspace** when the workspace migration runs. Newly registered users receive their own workspace.

## Demo account
- Select **🎮 Explore Demo Account** on the login page for one-click access without registration or a password.
- The API provisions a dedicated `demo` / `demo_user` account and a separate `Demo Inventory` workspace containing fictional products, suppliers, and sales.
- Demo access is read-only and enforced by the API. Demo users cannot select another workspace, create workspaces, or modify inventory.
- Sessions use HTTP-only cookies, CSRF-token and trusted-origin checks, a 30-minute inactivity timeout, a four-hour absolute limit, and rate-limited sign-in. Up to ten demo sessions may be active at a time.
- No shared demo password or administrator credentials are published. The demo account's unusable random password is generated by the server.

## Public deployment
1. Configure the backend from `server/.env.example`. Set `NODE_ENV=production`, a private MongoDB URI, a newly generated `JWT_SECRET`, and `CLIENT_URL` to the exact HTTPS frontend origin(s).
2. Set the frontend's `VITE_API_URL` to the deployed HTTPS API URL ending in `/api`.
3. Use HTTPS for the frontend and API so secure cookies work. Allow only trusted origins; do not allow dynamic wildcard origins.
4. Configure MongoDB access controls and backups with your hosting provider. Never put database credentials, signing secrets, or real user data in this repository.
5. Start the API. It creates the demo account and isolated sample workspace automatically; no public demo credentials or manual production database seeding are required.

AI forecasting and report views include sample/placeholder experiences.
